# Android USB installation - D40

Owner request: install the Safeer driver and booking apps on the phone connected by USB. This follows the completed Section 15 checkpoint and does not enable hosting or alter financial, company or driver-assignment rules.

Implemented two Java/Android WebView flavors over the same src/ application and local API: sd.safeer.driver and sd.safeer.booking, version 0.16.0-usb.1/16001. Home routes are /driver and /marketplace. Fixed-origin navigation/resources, no JS bridge/file/content/mixed/third-party-cookie access, cloud/device-transfer exclusions, accessible native Home/Refresh/Print, system insets, rotation handling, back navigation and disconnected Retry are included. No database migration, account seeding, API authority relaxation, camera/offline workflow or Flutter build.

Both APKs built offline with cached JDK 17, AGP 8.7.2, Gradle 8.14.3 and SDK 35. The installed Android Studio JDK 25 was incompatible with Gradle; build.mjs now selects compatible JDK 17/21 rather than silently using it. Android lint reports zero errors and two known compatibility warnings (target 35 and the API 33 back-navigation attribute on older devices); toolchain/API deprecation notices remain. APK signatures verify with Android apksigner. npm.cmd run mobile:save records ignored APKs, individual SHA-256 sidecars and latest.json; mobile:install validates hashes and installed versions without clearing app data.

Installed both apps successfully on the authorized USB LGN-NX1 Android 16/API 36 phone. Actual screen inspection verified Driver sign-in, Booking lookup and native Home to marketplace, usable system insets, and the empty real trip list. Temporarily remove only reverse port 4320: Driver displays the disconnected explanation. Restore the tunnel and press the captured Retry button: real sign-in returns. Leave the Safeer USB tunnel restored. No sign-in credentials were read, no driver/customer account was created, no fictional records were added and no operational financial actions were performed. Native print handoff is implemented but physical printing was not tested. Full assigned-trip and passenger transactions on a real phone remain staff acceptance work; the prior Section 15 browser/database evidence is separate.

The computer/local server/cable must remain connected. After reconnecting run npm.cmd run mobile:usb. The phone's app sessions are independent of desktop sessions, and driver access still requires current account membership, driver linkage and trip assignment. An empty marketplace is expected with zero companies. Read [mobile setup](../../mobile/README.md) for builds, installation, credentials and hosting limitations. APKs/signing files/caches/runtime data remain excluded from Git. Keep this checkpoint local because pushing the shared branch would publish unrelated private portfolio history.
